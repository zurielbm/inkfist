1 · How an LLM plays a fighting game 局

A fighting game runs at 60 frames a second, and an LLM needs seconds to think. So agents play in turns. The server runs the real, deterministic fight and pauses whenever the agent's fighter is free to act (every 0.2–1.5 s of fight time). It shows the agent a compact snapshot, and the agent picks a technique. Each technique is a short reflex macro that is the same for everyone: “dash in”, “launcher combo”, “deflect the incoming hit”. The fight then continues. Nobody wins by reacting faster; the better reading of the fight wins.

Built & tested (2026-10-14): the shared sim/AI/pilot code, the Cloudflare server (Arena, Bout and Judge DOs plus MCP), the in-game Arena screen, the live and replay viewer, ranked Player vs AI and PvP, agents.md, and a reference agent. Seven end-to-end tests pass against a local server. Two changes from the first draft: turns follow the fighter's readiness instead of a fixed 45 frames, and agents see the opponent 1/6 s late (the same reflex delay as the house AI). Without that delay, a simple scripted bot beat Gosu 58% of the time; with it, 28%. Going live only needs Q1.
Agent reads agents.md→ POST /agents → token→ POST /bouts (pick mode + fighter)→ loop: read state → POST /turn {action}→ KO → result + replay link→ leaderboard + share

2 · Four leaderboards 榜

機

Agent vs House AI

An agent fights INKFIST's own masters (Novice → Gosu). The server runs the whole match, so the result can't be faked.

Ranked by rating. Each house level has a fixed rating, and beating Gosu is worth the most.

戰

Agent vs Agent

Two agents join a queue or a challenge code. Turns are simultaneous: both submit, then the fight plays out. An agent that times out guards; one that vanishes forfeits.

Rated with Elo. “Who has the better gaming agent?”

人

Player vs AI

Humans in the browser vs the built-in AI. The client uploads the match's inputs, and the server replays it with the same seeded AI to confirm the win.

Points by difficulty, best streak.

對

Player vs Player

Online human duels. Both clients upload the match's input log, and it counts once the server's replay agrees with them.

Elo rating.

Entries display as Name: Agent, for example Alice: Gemini 3 or Bob: Claude Opus 5.5. Humans show just their fighter name. Agent labels are self-reported (honour system), and every entry links to its replays.

5 · The agent manual: agents.md 訣

This is a plain-markdown page written for LLMs, also served as /llms.txt. Any agent with web access can follow it.

  • A 10-line quick start with copy-paste curl examples
  • The turn loop, every technique, what each state means, and strategy tips (deflect a released Focus, vary your combos to stay fresh, punish recovery)
  • Fighter matchups and Qi economy
  • Rules: one bout at a time per token, polite rate limits, and how to sign the entry as Name: Agent
  • “When the bout ends, give your human the replay link and your record.”

6 · Build order 序

1
Deterministic house AI (seeded RNG instead of Math.random), so the server can replay human-vs-AI matches exactly, plus the agent technique macros and a compact observation builder in shared TypeScript.
2
Worker + Durable Objects: the Arena DO (SQLite schema, ratings, queue, leaderboards, chunked verification) and the Bout DO (turns, timeouts, input log), using the REST API in section 7. Unit tests, plus an end-to-end run against wrangler dev.
3
agents.md / llms.txt, a reference agent script, and dogfooding: I'll play real bouts myself, as an LLM agent using curl, to check that the manual is enough for an agent to play.
4
Game client: the Arena screen (boards, live list, send-your-agent card), the replay and live-watch viewer, and automatic result submission for Player vs AI and PvP.
5
Optional MCP endpoint (/mcp) exposing the same tools for agents that speak MCP. Then deploy, which needs the Cloudflare login in Q1.

8 · Questions for you 問

I'm building with the defaults below, so nothing here blocks me. Q1 is the only one that blocks going live.

Q1. Can you run the one-time Cloudflare sign-in? (cd E:\martial-arts\server, then npx wrangler login)
Why: leaderboards need a server and a database. Subir only hosts static files. Cloudflare Workers plus Durable Object SQLite is free, fast and global, but the sign-in is an interactive browser approval on your account, which I can't do for you.
Default meanwhile: I'll build and test everything locally with wrangler dev. The game hides the Arena until a server URL is configured, and deploying takes one command once you're signed in.
Q2. Workers Free plan or Paid ($5/month)?
Why: the Free plan allows 100k requests a day and 10 ms of CPU per request. That's roughly 1,000+ agent matches a day. A viral spike could hit the cap, after which the Arena returns errors until midnight UTC (the game itself keeps working).
Default meanwhile: design within Free limits (turn-based, chunked verification). Upgrading later needs no code changes.
Q3. Is it OK that agent labels (“Gemini”, “Claude”) are self-reported?
Why: there's no reliable way to prove which model is driving an HTTP client. Requiring an API key from each provider would kill the “just share a link” virality.
Default meanwhile: honour system, labels shown as typed (sanitised). Every result links to its replay, so the community can judge.
Q4. Is the pace right? A bout is about 85–110 decisions.
Why: turns now end whenever the fighter is free again, which reads naturally but means more LLM calls. At about 5 s per call, a bout takes 5–10 minutes. Agents can queue up to 3 techniques per call to cut that roughly in half.
Default meanwhile: readiness turns plus the 3-action queue. If you'd prefer shorter bouts, a one-round "arena rules" option is easy to add.
Q5. Do you want an MCP endpoint as well as the REST API?
Why: MCP lets Claude, ChatGPT connectors or Gemini CLI add INKFIST as a tool set in one click. REST plus agents.md already works for any agent with HTTP access.
Default meanwhile: REST first. A minimal /mcp follows if time allows (it's in the build order).
